## Educational corrections beyond the questions

All module introductions, cheatsheets, flashcards, use cases, labs, recommended links, study plans, and root guidance were reviewed. Cross-topic boilerplate that recommended unrelated services for generic elasticity was replaced with requirement-specific explanations. Major corrections include:

| Area | Corrected teaching and primary evidence |
|---|---|
| Access and governance | Temporary role credentials, explicit-deny precedence, least privilege, SCP ceilings rather than grants, and management-account exceptions. [IAM](https://docs.aws.amazon.com/IAM/latest/UserGuide/best-practices.html), [SCPs](https://docs.aws.amazon.com/organizations/latest/userguide/orgs_manage_policies_scps.html). |
| Compute and availability | EBS attachment within one AZ, Regional EFS for shared NFS, placement failure boundaries, ELB health-check opt-in for Auto Scaling, externalized state, surviving capacity, and pricing commitments separate from capacity guarantees. [EBS](https://docs.aws.amazon.com/ebs/latest/userguide/ebs-volumes.html), [Auto Scaling](https://docs.aws.amazon.com/autoscaling/ec2/userguide/health-checks-overview.html). |
| Storage and recovery | Versioning versus availability, compliance retention limits, storage-class failure tolerance and retrieval behavior, RPO versus RTO, backup restoration versus running standby, and regional versus AZ failure scope. [S3 Versioning](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Versioning.html), [recovery objectives](https://docs.aws.amazon.com/wellarchitected/latest/framework/rel_planning_for_recovery_objective_defined_recovery.html). |
| Networking and delivery | Public routes versus addressing, stateful security groups versus stateless NACL return rules, same-Region S3 gateway endpoints, regular S3 origins for CloudFront OAC, approximate DNS-weighted traffic, nontransitive peering, PrivateLink service boundaries, and Direct Connect encryption requirements. [Direct Connect](https://docs.aws.amazon.com/directconnect/latest/UserGuide/encryption-in-transit.html), [peering](https://docs.aws.amazon.com/vpc/latest/peering/vpc-peering-basics.html). |
| Databases | Unreadable standby in an RDS Multi-AZ DB instance versus readable instances in a Multi-AZ DB cluster, asynchronous read-replica lag, GSI eventual consistency, and both MREC and MRSC global-table modes. [RDS deployment types](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/Concepts.MultiAZ.html), [DynamoDB consistency](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/HowItWorks.ReadConsistency.html). |
| Messaging and serverless | Standard-queue duplicates, FIFO per-group order and bounded send deduplication, independent consumer queues, business idempotency, Lambda partial-batch failures, reserved versus provisioned concurrency, and API keys distinct from authorization. The lab explicitly addresses crash consistency between idempotency state and side effects. [Lambda with SQS](https://docs.aws.amazon.com/lambda/latest/dg/with-sqs.html), [API Gateway API keys](https://docs.aws.amazon.com/apigateway/latest/developerguide/api-gateway-api-usage-plans.html). |
| Containers | Orchestration versus compute, task versus execution roles, service versus underlying compute scaling, and App Runner closed to new customers while existing customers retain service access. [App Runner availability](https://docs.aws.amazon.com/apprunner/latest/dg/apprunner-availability-change.html). |
| Analytics and ML | Catalog metadata versus ETL, partition pruning and columnar layout, buffered Firehose delivery versus replayable streams, migration versus arbitrary transformations, pretrained service capabilities, SageMaker AI naming, and Bedrock as optional architecture context without invented exam frequency. [Glue components](https://docs.aws.amazon.com/glue/latest/dg/components-overview.html), [SageMaker AI](https://docs.aws.amazon.com/sagemaker/latest/dg/whatis.html). |

New tracing guidance uses OpenTelemetry rather than an unqualified recommendation of X-Ray SDKs/daemon in maintenance mode. The X-Ray service itself is not described as retired. [CloudTrail data events](https://docs.aws.amazon.com/awscloudtrail/latest/userguide/logging-data-events-with-cloudtrail.html), [X-Ray notice](https://docs.aws.amazon.com/xray/latest/devguide/xray-daemon.html). |

[KMS rotation](https://docs.aws.amazon.com/kms/latest/developerguide/rotate-keys.html), [six pillars](https://docs.aws.amazon.com/wellarchitected/latest/framework/the-pillars-of-the-framework.html). |

## Remaining limitations

- No known unresolved question-key/explanation contradiction remains after this review. AWS behavior, pricing, account eligibility, scope, and service lifecycle can change; verify current primary sources before provisioning or scheduling an exam.
- No AWS resources were provisioned and no paid AWS lab was executed during this repository review. - The 145 community practice questions are neither an official exam nor a statistically calibrated readiness predictor. Equal mini-practice blocks do not reproduce the exam weighting, and option wording/length is not an answer strategy.
- The original flattened banner contains Portuguese lettering. It is preserved as branded artwork with an English caption/alternative text. Some linked community repositories, courses, and social destinations may use Portuguese; they are external resources.
- This release does not publish an English GitHub Pages site. The existing `main`-only workflow and Portuguese Pages deployment remain protected. The portal runs locally or from a downloaded file and retrieves the English branch over the network.
