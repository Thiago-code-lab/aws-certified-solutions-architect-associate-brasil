# How to Contribute

Thank you for contributing to this AWS Brazil community repository.

## Ways to Contribute

- Correct technical or writing errors.
- Improve clarity of explanations and review materials.
- Suggest short labs and use cases relevant to SAA-C03.
- Update official AWS links when necessary.

## Recommended Workflow

1. Open an issue with clear context.
2. Create a branch with a descriptive name.
3. Make small, focused changes.
4. Open a pull request against `saa-c03-english` with a summary, rationale, and list of changed files. Keep the English edition separate from `main`.

## Editorial Standards

- Public content in American English (en-US) on this branch.
- Objectivity, technical precision and architectural focus.
- Avoid long and redundant texts.
- Prefer current, deployment-specific AWS documentation over historical translation parity. Correct an incorrect answer, even when its original letter or wording changes.
- Practice questions must state their assumptions, contain four distinct alternatives with one defensible answer, explain every distractor, and cite applicable AWS primary documentation.
- Retain stable question IDs. Record reviewed changes in the editorial manifest and question audit, including the baseline and approved content digests; do not refresh digests without reviewing the actual diff.
- Distinguish exam scope from service availability, and measured lab evidence from a design-only walkthrough. Never promise a pass result or a zero-cost deployment.

## Pre-PR Checklist

- Readable and consistent Markdown.
- Links working.
- Coherent AWS terminology between modules.
- Run the content, educational regression, portal, and support suites described in [the release audit](./docs/english-edition/README.md).
- Keep the 31-module layout, original license and branding, progress storage keys, and `main`-only Pages guard intact.
